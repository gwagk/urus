# DTMC URUS

**One Stop Endpoint Utility**

> ลีน คลีน ไม่บวม — เครื่องทำสิ่งที่เครื่องควรทำ คนตัดสินใจในสิ่งที่คนควรตัดสินใจ

## ทำไมเราจึงสร้าง DTMC URUS

DTMC URUS เกิดจากปัญหาง่าย ๆ ในงานจริง: การเตรียมและดูแลเครื่องปลายทางหนึ่งเครื่องมีหลายขั้นตอน หลายคำสั่ง และหลายเครื่องมือ ตั้งแต่การตั้งชื่อเครื่อง การติดตั้ง Wazuh Agent การตรวจสอบสถานะ ไปจนถึงการวิเคราะห์ ซ่อม และกู้คืนเมื่อ Agent มีปัญหา

ขั้นตอนเหล่านี้ทำได้ด้วย BAT, PowerShell และคำสั่งต่าง ๆ แต่เมื่อขยายไปยังหลายด่านและให้ผู้ใช้งานหน้างานเป็นผู้ดำเนินการเอง ความซับซ้อนกลายเป็นความเสี่ยง: ใช้ไฟล์ผิดรุ่น, ทำขั้นตอนซ้ำ, กดติดตั้งซ้อน, ข้ามการ Restart, หรือเห็น Service RUNNING แล้วเข้าใจว่า Agent ทำงานสมบูรณ์แล้ว

URUS จึงไม่ได้ถูกสร้างเพื่อเพิ่มระบบอีกระบบหนึ่ง แต่เพื่อ **ลดสิ่งที่ผู้ใช้ต้องจำ** และรวมขั้นตอนที่พิสูจน์แล้วว่าใช้ได้จริงให้เป็นเครื่องมือเดียว

## URUS เกี่ยวข้องกับอะไร

DTMC URUS เป็นเครื่องมือฝั่ง Endpoint สำหรับช่วยนำการจัดการเครื่องตามแนวทาง DTMC ไปใช้กับ Windows PC หน้างาน และเชื่อมเครื่องเข้าสู่ระบบ Wazuh/OMNIX ที่มีอยู่แล้ว

URUS ไม่ได้แทน Wazuh, OMNIX หรือระบบส่วนกลาง และไม่ได้สร้างนโยบายใหม่ หน้าที่ของมันคือทำให้การปฏิบัติที่เครื่องปลายทางเป็นขั้นตอนเดียวกัน ตรวจสอบได้ และลดการพึ่งพาคำสั่งทางเทคนิคของผู้ใช้

## แนวคิดหลัก

URUS อ่าน **สถานะจริงของเครื่อง ณ เวลาที่เปิดโปรแกรม** แล้วตัดสินใจว่าขั้นตอนใดควรทำต่อ ไม่เดินหน้าต่อเพียงเพราะจำได้ว่าครั้งก่อนทำอะไรไว้

วงจรเริ่มต้น:

`RENAME → RESTART → INSTALL → VERIFY → HEALTHY`

การ Rename ถือเป็น transaction ที่ต้องจบด้วย Restart ก่อนเดินต่อ เมื่อ Windows กลับมา URUS จะตรวจชื่อเครื่องจริงอีกครั้ง แล้วจึงเข้าสู่การติดตั้งและตรวจสอบ Agent

เมื่อเครื่องเข้าสู่ HEALTHY แล้ว URUS เปลี่ยนบทบาทจากตัวติดตั้งเป็นเครื่องมือบำรุงรักษา:

`CHECK → DIAGNOSTIC → REPAIR → CLEAN → RECOVER`

หากต้องถอนและติดตั้งใหม่ วงจรก็สามารถกลับไปเริ่มที่ INSTALL ได้อีกครั้ง

## หลักการออกแบบ

- **One Stop:** ผู้ใช้เปิดเครื่องมือเดียว ไม่ต้องสลับ BAT, PowerShell และตัวติดตั้งหลายชุด
- **State-driven:** เชื่อสถานะจริงของ Windows และ Wazuh มากกว่าความจำหรือ flag เพียงอย่างเดียว
- **One machine, one transaction:** ไม่ให้คำสั่งที่ขัดกันทำงานซ้อนบนเครื่องเดียวกัน
- **Verify before success:** Service RUNNING หรือ Port เปิดอย่างเดียวไม่ถือว่า HEALTHY
- **Human at decision points:** Popup ใช้เมื่อคนต้องตัดสินใจหรือดำเนินการจริง ไม่ใช้เล่าเรื่องที่โปรแกรมตรวจเองได้
- **No leftovers:** งานชั่วคราวและกลไก Resume ต้องไม่กลายเป็น Startup หรือขยะถาวรหลังงานจบ
- **Field first:** หน้าจอและขั้นตอนต้องให้เจ้าหน้าที่หน้างานใช้ได้โดยไม่ต้องรู้ PowerShell หรือโครงสร้างภายในของ Wazuh

## ที่มาของชื่อ

**URUS** มาจากคำมลายูที่มีความหมายในแนว *จัดการ / ดำเนินการ / ดูแลให้เรียบร้อย* ซึ่งตรงกับบทบาทของโปรแกรม: ไม่ได้ทำเพียงการติดตั้ง แต่ดูแลวงจรของ Endpoint ตั้งแต่เริ่มต้นจนถึงการบำรุงรักษาและกู้คืน

ชื่อเดิม **SPLAT** ยังคงเป็นรากของแนวคิดและประสบการณ์ที่นำมาพัฒนา URUS แต่ URUS ขยายขอบเขตจากเครื่องมือติดตั้งไปสู่ **Endpoint Lifecycle Utility** แบบครบวงจร

## Lifecycle

```text
NEW / PROVISIONING
      │
    RENAME
      │
    RESTART
      │
    INSTALL
      │
    VERIFY
      │
   HEALTHY
      │
      ├── CHECK
      ├── DIAGNOSTIC
      ├── REPAIR
      └── CLEAN / RECOVER
```

## Current status

**v0.5-rc1 — Release Candidate**

Current validation target:

`Fresh machine → Rename → Restart → Resume → Install → Verify → Healthy`

The RC is intended for controlled field testing before a stable release. พบปัญหาที่ขั้นตอนไหน ให้หยุดและแก้ที่ state นั้น ไม่ข้ามปัญหาเพื่อให้ flow ดูเหมือนสำเร็จ

## Development note

DTMC URUS พัฒนาจากปัญหาหน้างานจริงและการทดสอบแบบวนรอบ:

`DESIGN → BUILD → QC → FIX → RE-QC → PILOT → RELEASE`

แต่ละ version จึงไม่ใช่เพียงเลขรุ่นใหม่ แต่คือสิ่งที่เรียนรู้จากรุ่นก่อนหน้าแล้วนำกลับมาทำให้ระบบง่ายขึ้น ปลอดภัยขึ้น และเหมาะกับคนใช้งานจริงมากขึ้น
